# Eternal Ascension

A 2D top-down open-world xianxia cultivation action RPG, built with **Godot 4.4** (GDScript).

Current build: **1.0.1**, the release build. It is a complete playable sandbox: a streamed
province, a populated settlement with scheduled NPCs, real-time frame-data combat, cultivation
with breakthroughs, deterministic procedural items, nine hidden-realm families with their own
wardens and inheritances, four quest chains, twelve sect storylines, a four-thread narrative
archive and one irreversible ending, plus a crash-safe save system. The release adds a title
screen with painted key art, a synthesized ambient score, a settings and accessibility layer,
a live character sheet, and Linux and Web export presets.

## Run it

### In the Godot editor

1. Install [Godot 4.4](https://godotengine.org/download) (standard build, not .NET).
2. Open `game/project.godot` as a project.
3. Press **F5**. The game opens on the title screen; **Begin a new life** starts creation,
   **Continue** resumes the highest populated save slot.

### A built release

`game/export_presets.cfg` carries two release presets. With Godot 4.4.1 and its export
templates installed:

```bash
mkdir -p game/build/linux game/build/web
godot --headless --path game --export-release "Linux"
godot --headless --path game --export-release "Web"
```

The Linux preset writes one self-contained executable to `game/build/linux/eternal-ascension.x86_64`;
the Web preset writes `game/build/web/index.html` plus its wasm and pck. Release notes and known
limits are in [`docs/RELEASE_NOTES.md`](docs/RELEASE_NOTES.md).

## The playable loop

1. **Create a character** — a random name, a weighted spiritual root (Mortal → Primordial),
   and six free attribute points.
2. **Azure Cloud Market** — a settlement of ~19 NPCs with daily schedules, who also cultivate
   while you are away: over the days their realms, arts and gear rise (and failed breakthroughs
   injure them). Elder Bai stands by the sect hall and starts *The Azure Cloud Invitation*: talk,
   slay 3 beasts, gather 2 spirit herbs, attune at the shrine, return. Reward: a technique, a
   passive, spirit stones.
3. **Fight** — enemies telegraph, then strike. Your weapon's own moveset chains on right-click,
   techniques spend Qi on left-click and come in six deliveries: melee arcs, travelling sword-Qi
   bolts, telegraphed area spells, summoned beasts, timed body arts and movement steps. Poise,
   stagger, knockback and dodge i-frames apply to all of them.
   Hold guard to meet a blow: the opening moments parry it for free, and a held block spends Qi until
   the reserve fails and the ward breaks. Kills drop generated items you can pick up and auto-equip.
   A humanoid beaten below a quarter health can instead be taken alive with **H** (twice: subdue,
   then bind), or finished with a strike as before.
4. **Cultivate** — meditate to gather Qi, advance through 10 sublevels, then face a
   breakthrough at the peak. Failure causes Qi deviation, meridian damage, or regression.
5. **The Rifts** — nine hidden realms wait to be found around the market, from the *Tomb of the
   Hollow Moon* to the *Forbidden Domain*: walk near a site, hear a rumor, or read the notice board.
   Each rift keeps its own opening cycle, shown on the map and route list; a sealed rift refuses entry
   and names its next opening. Every family has its own layout, palette, hazards, guards, loot,
   warden and inheritance altar; claiming an altar requires passing its trial. Saves are blocked
   inside; exit to save.
6. **Save/load** — F5/F9. Saves are atomic, checksummed, backed up three deep, and recover
   automatically from a corrupted newest file.

## Verification

```sh
godot --headless --path game --import                                    # import check
godot --headless --path game res://tests/run_tests.tscn                   # unit + content
godot --headless --path game res://tests/integration.tscn                 # real-scene smoke
godot --headless --path game --quit-after 240                             # boot smoke
mkdir -p game/build/linux game/build/web
godot --headless --path game --export-release "Linux"                    # release build
godot --headless --path game --export-release "Web"                      # release build
```

Each suite prints `RESULT: PASS n / FAIL 0` and exits `0` on success. CI runs the same
commands (`.github/workflows/ci.yml`). The unit suite covers content validation, attribute
formulas, the stat pipeline, RNG determinism, item generation, cultivation, combat curves,
world/chunk streaming, NPC schedules, quests, hidden-realm generation and save/load including
corruption recovery and schema migration. The integration suite drives the real main scene:
allocating attributes, attacking through the frame state machine, killing, looting,
meditating, breaking through, entering/exiting the hidden realm, and saving/loading.

## Implemented

- Six uncapped attributes; one `StatBlock` pipeline (attributes → flat → percent → equipment → realm).
- 12 spiritual root tiers with weighted generation, purity, affinities, cultivation multipliers.
- 12 realms × 10 sublevels as one data-driven ladder: every sublevel raises Qi capacity (1 → 4.15×, banded Early/Middle/Late/Peak), every realm is a multiplier with cumulative unlocks and one realm art, breakthroughs scale with behaviour and their failures cost something, and the twelfth realm is a guarded apex.
- Realm arts and unlocks: each realm declares what it opens (Qi Sense, Dash Cancel, Meridian Opening, Technique Weaving, Flight, …) and one art whose mods feed the stat pipeline; dash cancel (realm 2) really lets a dodge abandon a swing, and technique weaving (realm 5) really cuts Qi cost and cooldown by 10%.
- Weapon framework: every weapon category — sword, saber, staff, whip and bare hands — owns its own light-attack moveset. Each category carries its own chain of strikes (frame data, arc, damage multiplier, poise and knockback), its own reach, speed and weight, and a chain window; the equipped weapon picks the moveset, chains advance and wrap while the window is open, and a weapon strike costs no Qi while techniques stay on their own press. Weapon categories load from `data/weapons.json`, generated weapons carry their category, and old items resolve through their base id to the same moveset.
- Defense: hold guard for a frontal ward. Its first moments are a parry window that turns a blow aside
  for free and throws the force back at the attacker; past it, a block spends Qi per absorbed blow while
  armour and resistances still soften the rest. Guard only covers the front, never a hazard or a
  tribulation bolt, and an unpaid block breaks instead: the blow lands harder, poise is emptied, the
  reserve is lost and the ward cannot be raised again for a moment. A raised guard cannot attack or
  sprint, and a dodge drops it.
- Combat architecture: one shared rules layer (`Combat` + `Poise`) for both the player and every enemy — 60 Hz frame phases with attack-speed timing, arc or full-circle hitbox geometry that honours facing, reach and body radius, poise meters that stagger on the breaking blow, knockback impulses, and interruption of a wind-up but not a committed swing. The player now has poise and stagger of his own, and enemy blows carry poise and knockback; a stagger cancels meditation and can cancel an attack in startup.
- Lifespan and aging: the body has an age read from the world calendar (one year every 24 days of play). Past 60% of its realm's lifespan it enters middle age, old age and fading years; STR, DEX and AGI decline up to 35% while WIS, INT and CHA are spared, with a one-time warning at each stage. At the lifespan the run ends with a quiet summary screen (ENTER begins a new life), an ended run cannot be saved, and a dead save loads back into that screen. Realm 12 is ageless.
- Enlightenment: understanding accrues from real play — meditating with a method, every kill, surviving a tribulation, breaking through — and fills a comprehension meter. A full meter rolls a deterministic, weighted epiphany among insights you qualify for (by realm and practised method); an insight is permanent and adds its mods to the one stat pipeline, with thirteen in `data/enlightenments.json` from Still Water Clarity to Primordial Glimpse. The meter and learned insights are shown on the HUD and saved.
- Playable tribulations: pressing G at the peak starts the realm's own heavenly trial — a telegraphed, staggered bolt pattern in a bounded circle. Dodge bolts to survive each wave (i-frames work, armour and evasion do not), earn a perfect-wave composure bonus of up to +12% on the breakthrough roll, or fall inside the circle and take the failure fallout without a roll. Eleven data-driven trials (`data/tribulations.json`) run from a three-wave meridian test to the seven-wave primordial sky, each with its own colour, bolt count, pacing, scatter and damage. Saves are refused mid-trial; loading abandons it.
- Breakthrough preparation and method tribulations: a scorched tribulation ground beside the shrine banks up to three preparations (60 stones each) which raise the roll by 6% apiece, lighten Heaven by 10% and soften failure's wound and corruption — all spent by the attempt, win or lose. Each of the seven methods reshapes the tribulation itself: sword intent needs recent combat, dual cultivation needs a partner, the celestial path needs night, a conditioned body trades a heavier heaven for gentler failure, and the Blood Sea lends chance while making failure bite harder.
- Technique combat: six deliveries share one frame machine, one Qi cost and one damage path — melee arcs, projectiles that pierce and die at their range, spells that telegraph and bloom at a point ahead of the caster, summons that hunt for a duration and carry a share of the blow, timed body arts whose mods enter the one stat pipeline, and movement steps with their own i-frames. Eleven techniques live in `data/techniques.json` — Piercing Thrust carries sword Qi, the Ninefold Sealing Array is a spell, Nine Beast Stampede calls a pack, Golden Bell Cover is a body art and Cloud Step is a movement art — `TechniqueCombat` is pure, `DB.validate` checks each kind's payload, and Q cycles every known art so one learned after the six-slot bar is full is never stranded.
- Deterministic item generation: 4 rarities, tiered prefixes/suffixes, stable IDs, auto-equip.
- Equipment and passives feed real combat stats through `StatBlock`.
- Seamless streaming over a 12×12-chunk province: pure payload generation on worker threads, nodes built on the main thread, and a deterministic seed identity for every chunk.
- Chunk deltas: harvested resources are remembered per chunk with the day they were taken, saved with the run, and restored when the chunk streams back in.
- Background regrowth: chunk herbs return a few days after being harvested, evaluated from the clock when the chunk reloads rather than ticked per frame.
- Qi and meridians: twelve permanent channels opened in order at the meridian hall for Qi and stones, each raising capacity and adding a stat; Qi contamination from blood practice and failed breakthroughs (up to −50% gain) purged at the shrine for 30 stones; and per-biome Qi density multiplying meditation (marsh rich, ash poor).
- Cultivation methods with real loops: seven methods differ by what feeds them (sitting, STR, recent combat, absorbed blood, kills, a nearby partner, the night sky), each builds its own insight for up to +20% cultivation, and a method stele lets you switch for 150 stones only to a method you qualify for.
- Technique mastery: five tiers earned by landing a technique, raising damage while cutting Qi cost and cooldown, shown per slot on the technique bar and saved per technique. Falling Petal Cut is hidden from the starting kit and can be bought from Instructor Rui (180 stones) or learned for free by watching the practising disciple three times, both gated on realm and DEX.
- Item architecture: every item is one canonical record — fixed fields, a stable `item.*` id, a known slot, clamped rarity/level/value and a count — and every route into the satchel (drops, shops, saves, loads) passes through it. Weapons hold 300 points of durability and armour 400; a swing wears the weapon, a damaging blow wears the armour, worn gear still works and broken gear contributes nothing at all until it is mended. The inn mends every worn piece for stones priced by what is missing and how rare the piece is. Materials stack to 20 and consumables to 10 by slot, base and name, so two heaps of spirit ore are one line and two swords never are; stacks sell whole and read as `Name xN`. Saves carry the exact condition and count, schema 2 migrates older saves by filling both, and the loader drops any item it cannot represent instead of trusting the file.
- Nine realm families: `data/hidden_realm_families.json` holds the Tomb, Immortal Ruin, Beast Realm, Forgotten Battlefield, Heavenly Garden, Abandoned Sect, Trial Realm, Spatial Fracture and Forbidden Domain. Each family owns a distinct 3–8-cell layout in `data/hidden_realm_templates.json`, a palette, hazard damage, enemy tier and roster, a warden, a loot table and an inheritance altar. Nine access sites in `data/realm_access.json` place one portal for each family around the market, each with its own reveal radius, opening cycle, rumor and discovery line. Discovery and opening windows are shared with the M63 gate; non-tomb layouts derive their seed from the world seed and site id, so no new save key is needed and the historic tomb keeps its saved `realm_seed`. Entering a family builds only that family's layout and chest ids, and `DB.validate` checks families, layouts and sites against each other.
- Inheritances: `data/inheritances.json` holds three legacies for each of the nine families, from the tomb's Dustbound Legacy to the Forbidden Domain's The Name Returned. Every entry has a rarity (Common, Resonant or Transcendent), a weight, compatibility terms (realm, body tier, root affinity and attribute gates), a technique/passive/physique grant, and a trial. The altar filters the family's pool to what the claimant can accept, rolls the offer deterministically from the realm seed, then spawns that legacy's echoes; rarer legacies add a rival seeker. The trial has a countdown on the HUD, and killing every echo — rival included — grants the legacy, its relic where authored, and one altar piece. A claim is recorded per site, while the tomb's old `inheritance_taken` flag still loads and aliases its site entry. The trial is transient: leaving the realm or timing out returns the inheritance to the altar.
- Spirit beasts & bosses: four species in `data/spirit_beasts.json` — Moonfang Wolf, Stoneback Boar, Thundercrane and Gloom Serpent — live in the biomes their habitat map names, wear their own name, colour, numbers, bite status and core, and fight through the same behaviour archetypes as humanoids (a wolf circles and retreats, a boar holds its ground). Wild spawns are about half beast, and a beast drops a material core worth selling on top of ordinary loot. The Tomb of the Hollow Moon is guarded by the **Warden of the Hollow Moon**, a boss with a long bar at the top of the screen, three health phases (Hollow Guard, Moon's Wrath, Last Light), phase multipliers read live so it hits harder, moves faster and strikes sooner as it loses health, a status on its later blows, and beasts it calls when it changes phase. Each family's inheritance altar refuses to yield while its warden lives; killing it pays spirit stones and one guaranteed treasure-grade item, and the kill is saved by id so a cleared tomb stays cleared and a loaded save never respawns it. Phase thresholds are data, the phase rules are pure, and `DB.validate` checks thresholds, phases, adds and statuses. Eight further wardens guard the other families — the Broken Heaven, the First Beast, the Unfallen General, the Jade Gate, the Last Disciple, the Examiner, the Folded One and the Nameless Sovereign — each with its own phases, adds, colour, intro and reward.
- Combat polish: a landed blow freezes the fight for a few hundredths of a second through a real-time `Hitstop` timer — no engine clock is touched, a critical or heavy blow holds longer, and a second blow never extends a freeze it did not ask for — while the damage floats up as tinted numbers drawn in world space (critical hits larger and gold, status ticks in their own colour). Four data-driven statuses (burn, bleed, chill, shock) stack up to three times and refresh rather than replace: burn and bleed tick unblockable damage every half second, chill slows movement and shock raises damage taken. Fire, blood and formation arts carry them, three enemy archetypes apply them, they show on the HUD and above the body, and `DB.validate` rejects an unknown status. Combat sound is synthesized at startup — eight short 16-bit streams built from deterministic envelopes, no audio assets — and dispatched from bus signals for swings, hits, criticals, guards, parries, hurts, deaths and arts, with F2 muting. Statuses and numbers are transient and never saved.
- Enemy AI: four behaviour archetypes in `data/enemy_archetypes.json` — brawler, skirmisher, sentinel and Qi archer — share one pure brain (`EnemyAI`). A body patrols a circuit around its spawn until the player enters its aggro range and vision cone, then chases and remembers where the target was last seen; past its leash it walks home, loses interest and mends. Only so many bodies commit to a blow at once (the rest circle, and bodies push apart so a pack cannot stack), a skirmisher backs off after each strike and runs once when badly hurt, a sentinel guards a short leash behind a 140° arc, and an archer holds its firing band and shoots telegraphed Qi bolts through the same `Projectile` and the player's own `take_hit`. Every blow still winds up, so a stagger or a parry cancels it and stepping out of the arc dodges it; biome enemy tables and hidden-realm guards assign the archetype, and a non-aggressive body keeps the old training-dummy behaviour.
- Skill bars: three bars of six slots (`SkillBar`, 18 in all) hold the arts a body knows. Keys 1–6 pick from the active bar, `[` and `]` switch bars, and `Q` still reaches an art that sits on no bar or was learned after every slot was filled. `B` opens a drag-and-drop arrangement panel that freezes the run — drag a slot onto another to move or swap, drag one off the panel to clear it, drag an unplaced art in from the roster, or right-click to empty a slot. Every slot shows its own art's cooldown as a sweep and a tenth-second timer, so one art gathering never hides another that is ready. The layout is saved; a pre-M34 save derives one from the known kit, and unknown or duplicated ids are pruned rather than trusted.
- Passives with rules: requirements on attributes/realm/physique/affinity, mutually exclusive passive pairs where the first acquired wins, situational activation (wounded or karma) rebuilt only on threshold crossing, pair synergies applied through the stat pipeline, and manuals by the shrine that teach three new passives.
- Physiques: seven weighted innate bodies (Mortal Frame to Chaotic Spirit Embryo) that add stats through the normal pipeline, rerollable at creation with P, shown on the creation screen and HUD, inherited once at the realm altar only when strictly better, and saved.
- Spiritual roots: a hidden purity bonus that only applies once the Root-Reading Pavilion appraises the root, Spirit Root Marrow found deterministically in mines and ruins, and one-tier root evolution paid in marrow and stones, all saved.
- Procedural loot: base, rarity, affixes and values come only from the item's own `(seed, key, counter)` stream, so the same seed reproduces an item no matter what was generated before it. Every affix has three tiers gated by item level (a level-twelve treasure rolls the top tier, level-one gear cannot), affix pools are weighted with per-slot overrides and a zero weight removes an affix, selection never repeats an affix on one item, and the rolled tier is kept in the item's canonical save form and named in its description.
- Equipment rules: bases can require attributes or a realm and carry tags that conflict across slots — a wind charm refuses heavy plate and an INT 14 rod refuses an INT 10 body — enforced by one gate that auto-equip and manual wearing both call, with the refusal reason shown. `I` opens a gear screen that freezes play, lists worn slots and bagged pieces and shows a stat-by-stat comparison (base power plus every affix, read exactly as the stat pipeline reads it) before ENTER wears the piece.
- Unique relics: two hand-authored items with fixed rolls, lore and one source each — the Hollow Moon Blade from the Warden (returns Qi per kill) and the Cloudstep Sash from the tomb's inheritance altar (returns health per kill). They are never rolled by loot, are granted once per save by their source, read gold with a ◆ in every list, show their lore in the gear comparison, keep their flag and lore through a save, and a broken relic returns nothing just as it contributes no stats.
- Satchel grid, sorting and a storehouse: `I` opens everything carried as a 6×5 grid, one page holding thirty kinds, with the worn slots and the selected piece's stat-by-stat comparison beside it and ENTER wearing through the same rules a pickup does. `R` cycles five orders (stored, slot, rarity, value, name); sorting rewrites the satchel itself so the HUD strip, the shop and the grid cannot disagree about an index, and every order is total — ties break on name, stable id and insertion order, so the same satchel always lays out the same way. The market's storehouse (`E`) is a second container with sixty shelves: the cursor picks a side, ENTER moves a whole stack across, a full storehouse refuses a new kind with a reason but still accepts a stack that merges, and a stored deposit survives a save. Shelf contents and the chosen order are saved with the run and validated on load.
- Crafting at the forge: the Azure Forge is a real station in the settlement with a recipe list in `data/crafting.json` — five authored recipes from `base` to spirit iron, each with materials, stones, a realm gate and a failure chance. **Forge** spends the materials and stones and produces the authored base through `ItemGen` (which gained a `force_base` pin, so a recipe names exactly what it makes), **refine** rerolls every affix on a piece while keeping its base, level, rarity and wear, and **disassemble** breaks a piece into spirit ore scaled by its rarity and level; relics and materials refuse all three. A failed forge loses its cost, a failed refine leaves the piece untouched, and INT raises the quality roll that can lift a result one rarity step. Every attempt advances the attempt counter — failures included — so a retry rolls a fresh stream rather than repeating a failed one. Materials now carry their kind in the canonical item (`ore`, `herb`, `core`, `marrow`) with an id-prefix fallback for older saves, so costs are exact counts across stacks, and the attempt counter saves with the run under schema 2.
- Alchemy at the cauldron: `data/alchemy.json` names the Herb-Garden Cauldron and three pills — Qi Gathering, Mending and Cleansing — each with its herbs and cores, stone cost, realm gate, failure chance and one effect (restore Qi, mend wounds, purge contamination). `Alchemy.brew()` is pure in its stream and makes the authored consumable, and because a pill has no rarity, quality shows as **potency** instead: INT raises it continuously, the quality roll adds a discrete jump, and the result is stored on the item, so two pills of one base can differ. Potency is part of a pill's stack identity, so a strong pill never disappears into a weak stack. A found pill is drinkable exactly like a brewed one (the effect is looked up by base), and pills are drunk from the satchel with `U`; the pill is spent even at full health. A spoiled brew costs its herbs and makes nothing.
- Professions: the forge and the cauldron are not free skills. Each is a rank earned by finishing work — **Smith** and **Alchemist** begin at Apprentice and rise through Journeyman, Adept and Master to Grandmaster at 4, 10, 20 and 34 completed pieces. Every successful forge, refine or brew is one point of practice; a failure or a locked recipe earns nothing, and breaking gear down is free so it never levels anyone. Rank is spent on two things: a bonus to the quality roll (on top of INT, so a master smith reaches results an apprentice cannot) and a reduction of the recipe's failure chance, with a floor so no work is ever risk-free. Recipes and pills name the rank they need — the Jade Ring and Wind Charm want a Journeyman, the Spirit Iron Ring and the Cleansing Pill an Adept — and the panels list locked work with the rank it requires instead of hiding it. Only practice points are saved; the rank is always derived from them, and an older save is simply an untrained one.
- NPC database: every body carries a whole generated record, not just a name. `data/npcs.json` gives each archetype an attribute template and growth, a root-tier band, a physique pool, an art pool, a gear pool and a set of ambitions from the goal catalogue; `NpcDb.sheet(archetype, id)` derives attributes, a root, a body, up to two arts, worn pieces and two goals purely from the world seed and the person's stable id, so a save stores none of it. Arts are filtered through `Techniques.can_learn` and gear is generated through `ItemGen` and passed through the same `Equipment` gate the player uses, so a record can never claim a body knows or wears what it could not. Walking near anyone shows their dossier on the HUD — realm, six attributes, root and purity, body, arts, gear, ambitions, and what they remember of you. Talking records the meeting (`met`, count, day, regard) in `Game.npc_memory`; base disposition plus earned regard gives a standing from hostile to warm, and that memory is the only NPC state a save carries.
- Daily schedules: every resident follows a routine from `data/npcs.json` across a seven-day week. Day 1 is a Metalday and the last day is the **Restday**, when each archetype switches to its own `rest_schedule` instead of repeating the weekday — disciples sleep in, merchants keep a longer market, farmers visit the shrine. An entry may carry a `days` filter (guards drill on Lightday instead of patrolling the plaza), a range may wrap past midnight, and `Schedules.validate()` proves every hour of every day has exactly one owner, so a gap or an overlap is a boot-time data error rather than a body frozen mid-routine. Bodies route through the plaza when walking between spokes instead of cutting through walls; the HUD clock names the weekday and the dossier shows the current routine (`Training at the training yard until 12:00`) and whether the body is still walking. Routines have teeth: a sleeping NPC cannot be spoken to, greetings are drawn from the activity, and Instructor Rui only teaches in the training yard during the 08:00–12:00 block. This also uncovered and fixed Rui's schedule key, which had pointed at a nonexistent table since his introduction.
- NPC intelligence: the town notices trouble. Each archetype in `data/npcs.json` carries an `ai` block — `nerve`, `alert_range`, a `response` (`confront`, `flee` or `shelter`), a `refuge` and whether it shouts — and `NpcAi` (`game/systems/npc_ai.gd`) is the pure mind behind it: `nearest_threat()` finds the closest hostile inside the body's own range, `decide()` turns a sighting or a neighbour's shout into an order, and nerve is real, because a body ordered to confront but below `CONFRONT_NERVE` takes shelter instead. The scene watches hostile bodies inside the market ring every quarter second, only waking residents react (a sleeper is behind a door), and a new alarm is shouted once to everyone within earshot, so panic spreads from the guard at the gate to the merchant who never saw the beast. A guard closes to a hold gap and stands there, farmers run for the fields, merchants shut themselves in the tavern, and the reaction overrides the routine until the alarm runs out, when the body walks back into its schedule. An alarmed NPC answers with a warning instead of its trade and records no memory, and the dossier shows the alarm line and the body's nerve. Reactions are live state only: nothing about a threat is saved.
- Relationships: everyone stands somewhere with everyone else. `data/bonds.json` holds six warmth bands that tile −100..100 — enemy, rival, stranger, acquaintance, friend and sworn friend — each with a label, a blurb and a greeting, plus reciprocal tie kinds (`mentor`/`student`, `kin`) and a short list of authored pairs. `Relationships` (`game/systems/relationships.gd`) is the pure graph: every edge is directional, so Elder Bai's regard for Instructor Rui (46) and the instructor's regard for his teacher (58) are two independent numbers, and a resident's baseline feeling toward any other is a seeded draw from the pair's stable ids, never a symmetric half. Authored ties name an edge (`Mentor of Instructor Rui`) while the warmth band still decides behaviour. The player's own node is memory, not a second ledger: temperament plus earned regard reads through the same bands, so an unmet guard is a stranger at −5 and one who has been spoken to at the cap is a friend at 25. Bands have teeth — a friend within earshot calls a warning when the market is threatened, an enemy turns away and will not talk, and the band colours the greeting — and the dossier shows the bond and any authored ties. Nothing new is saved: the fabric regenerates from the seed and memory, and `DB.validate()` proves the bands have no gap or overlap and that ties and pairs refer to each other.
- Factions: standing is earned and spent. `data/factions.json` defines four houses — the Azure Cloud Sect, the Verdant Market League, the Market Watch and the Hollow Moon Cult — each owning archetypes or bosses, allies and rivals, a colour and a motto. `Factions` (`game/systems/factions.gd`) stores the player's raw standing −100..100 in a saved map and reads it through five bands (hostile, wary, neutral, trusted, honoured); a lawful house subtracts its memory of the player's notoriety from what it actually thinks, so a holding yard costs face without rewriting the record. Helping one house ripples: rivals lose half the act and allies gain a quarter, and the same rule applies to a completed Azure Cloud quest, a request answered for a resident's faction, and the fall of the Hollow Moon warden. The band is not decoration: its disposition shifts every member's standing toward the player in the dossier, and its price multiplier changes what the market league charges at the stall (selling stays on the one value curve). **K** opens a frozen standings screen with each house, band, value, effects and relations; the dossier shows the resident's faction line beside their personal bond. The standing map is an optional save key under schema 2, clamped and cleaned on load, and `Factions.validate()` proves the bands tile −100..100, each archetype and boss belongs to one house, and allies and rivals name each other back.
- The twelve sects: the province answers to twelve houses, not one. `data/sects.json` names **Heavenly Sword**, **Azure Cloud**, **Crimson Lotus**, **Thousand Beast**, **Celestial Formation**, **Blood Moon Palace**, **Eternal Medicine Valley**, **Shadow Veil**, **Thunder Sovereign**, **Frozen Heaven**, **Golden Cauldron** and **Void Scripture Pavilion** — each with a philosophy, a seat and territory, an economy, an internal fault line, a colour, and one signature method and technique. `Sects` (`game/systems/sects.gd`) is the read-only roster: `describe()`, `signature_line()` and `seat_line()` feed the codex, `row()` flattens an entry for the HUD, and `local_sect()` marks the one gate the player actually stands at. Where a signature art already exists in the playable tables it is linked (`method.sword`, `method.blood`, `tech.palm.azure_cloud`, `tech.formation.sealing_array`, `tech.beast.nine_stampede`, `tech.blood.crimson_moon`, `tech.palm.thousand_petals`); the rest are authored identities whose playable mechanics arrive with later milestones. The local house is tied to its standing faction, so the codex shows the player's real band beside it. **Y** opens a frozen codex listing all twelve in two columns with their seat, philosophy, arts, trade and fault line. `Sects.validate()` proves exactly twelve entries, unique names and signatures, real method and technique links whose kinds agree, valid colours, complete fields, and exactly one local gate naming a real faction. The roster is content, not state: nothing new is saved and schema stays 2.
- Sect hierarchy: every hall has a ladder. `data/hierarchy.json` holds seven rungs — Servant, Outer Disciple, Inner Disciple, Core Disciple, Elder, Deputy and Sect Master — each with an authority, a duty, a privilege and a standing/realm gate, plus the specialist Instructor and Guardian offices and an assignment table for every archetype and authored resident. `Hierarchy` (`game/systems/hierarchy.gd`) is the pure model: `for_archetype()` and `for_npc()` place people, `player_rank()` derives the player's station from the same effective Azure Cloud standing the gate already reads and from their realm, `next_rank()` and `missing_for()` say what the next rung still wants, and `station_line()`/`hud_line()` feed the dossier and vitals. The master's seat is currently held by the resident master; the model already accepts a vacant seat, so leadership opens as a data change when politics arrives. **N** opens a frozen screen listing all seven rungs and both offices with their holders by name, the player's own station, and exactly what the next rung requires. Rank is not a saved counter: acting for the sect raises standing, and the ladder reads the result. `Hierarchy.validate()` proves seven ordered levels with rising authority, one held seat at the top, two offices, complete duties and privileges, usable gates, and assignments that name real ranks and archetypes. Schema stays 2.
- Sect economy: service is paid in contribution. `data/sect_economy.json` sets the awards for a completed sect quest, an answered request and a fallen boss; a daily stipend for every rung with dues deducted from the pay; two donation rates (10 stones → 1 point, 50 → 6); and the quartermaster's three pill shelves at increasing contribution and rank. `SectEconomy` (`game/systems/sect_economy.gd`) is the pure ledger: `claim()`, `donate()` and `buy()` return the exact resulting purse and point totals without applying them, so a refused transaction can never leave half a cost behind, and rank gates compare the service's rung with the player's derived station through `Hierarchy.level()`. **O** opens a frozen ledger with today's stipend, both donation rates and all three services; arrows select, ENTER transacts, and a row that cannot be taken still shows why. A quartermaster pill is a real consumable generated from the same base table alchemy uses, with a saved purchase counter keeping its item id unique. Contribution, the last stipend day and the purchase counter are optional save keys under schema 2; contribution is clamped to the data cap and the day can be claimed once per world day. Schema stays 2.
- Sect politics: the council decides the seat. `data/politics.json` holds three blocs — Traditionalists, Reformists and Militants — each with a speaker, an agenda, base support, a ceiling of 100, and a lobbying price of 8 contribution for 10 support. `SectPolitics` (`game/systems/sect_politics.gd`) is the pure model: `support_for()` derives a bloc's support from its base plus the saved investment, `total_support()` sums the council, `lobby()` spends contribution only when the whole cost and the bloc's remaining room allow it, and `can_vote()` refuses a vote that is already open, below the Deputy station, or short of the 150-support threshold. Passing the vote sets `Game.sect_seat_open`, permanently opening the top rung; `Hierarchy.seat_available()` takes that saved result, so a player who also meets the Sect Master's 95 standing and realm 6 becomes Sect Master without any rank counter. **F3** opens a frozen council screen with each bloc's speaker, agenda, support bar and lobbying price, plus the vote and the exact rank or support it still wants. Lobby investment and the opened seat are optional save keys under schema 2, sanitized on load; `SectPolitics.validate()` rejects a missing or malformed council, duplicate blocs, empty identity fields, impossible support ranges, free or supportless lobbies, a vote that cannot be won or needs no lobbying, and an unknown minimum rank. Schema stays 2.
- The player's sect: a hall of one's own. Once the player holds the Deputy station and 500 spirit stones, **F4** offers three irreversible doctrines — Sword Creed (six members), Alchemy Creed (five members, richer levy) or Formation Creed (seven members) — each with its own name, motto and hall. Founding turns the fee into the hall's treasury (`PlayerSect`), which pays a 25-stone gift for each recruit. Recruitment is not a menu of strangers: a candidate must already be in the friend band, must not be in the party or the holding yard, and must fit the doctrine's roster. Each member pays `1 + realm/2` stones plus the doctrine's bonus when the hall settles its day. Member ranks are derived from realm (Initiate, Disciple, Steward, Elder), and member realms are never saved. The sheet — name, doctrine, founding day, treasury, member ids and last levy day — is one optional save key under schema 2, sanitized on load. `PlayerSect.validate()` rejects bad founding costs or ranks, wrong doctrine counts, duplicate or incomplete doctrines, invalid roster sizes or levies, and missing or out-of-order member ranks. Schema stays 2.
- Sect autonomy: the hall keeps its own days. Every world day it gathers the levy, pays one stone of upkeep per present member, adds the strongest member's two-stone steward bonus, and resolves one weighted event from a pure `Rng.stream_from(world_seed, "sect_autonomy", hash(hall name), day)` draw: quiet, a vein (+12), a village gift (+6), a dispute (−5) or a raid (−12, reduced to half by the Sword Creed and a quarter by the Formation Creed). Skipped days from rest or travel are settled one at a time, sixty at most per call, so a reload cannot reroll a bad day and the same hall on the same day always hears the same news. The strongest present member is the derived steward, never an appointment. The eight most recent day reports live in the sect sheet, and the F4 screen shows the steward, roster, treasury and hall report alongside recruitment. The event table, upkeep and doctrine guards are content in `data/sect_autonomy.json`, validated at boot; `PlayerSect.sanitize()` cleans the autonomy day and report, so schema stays 2.
- Party: friends can walk with you. Pressing **P** beside someone whose bond has reached the friend band (M50) asks them to join; pressing it again sends them home. `Party` (`game/systems/party.gd`) owns the roster rules — trust, unique membership, the hard ceiling and the player's derived `StatBlock.party_slots()` capacity, which CHAR raises — and the formation, so slot zero walks behind you and the flanks fall in from there. A companion is not an escort script: joining builds a `StatBlock` from that person's own generated attributes, worn gear and realm, so their blow is their real weapon and strength, their evasion and armour are their own, and their attack cadence follows their agility. They follow in formation, engage enemies within 280 paces, close to 42 and strike through the same `take_hit` path every other blow uses. Enemies pick the nearest body, player or companion, and enemy Qi bolts scan both, so a follower can draw a fight and take real damage; at zero health they go down, leave the roster and walk back to their routine at 40% health rather than dying. The HUD lists the party with realm, bond and health, and the only party state a save carries is the roster of stable ids under the optional `party` key — schema 2, cleaned on load.
- Captivity: a beaten foe can be taken alive. A hostile humanoid below 25% health can be **subdued** with **H** — the body drops, stops acting and shows a short window — then bound with **H** again, or finished with a strike that kills exactly as any enemy would, so kills, loot, elites and bosses are untouched. A captive is a person with a generated name, the realm they were beaten at and a saved loyalty, not an item: `data/captivity.json` owns two sets of terms (fair rations that cost upkeep and slowly win loyalty; harsh terms that extract nearly twice the work while burning loyalty), the loyalty ladder, escape chances, labour, bounties and the legal bands. `Captivity` (`game/systems/captivity.gd`) is the pure trade: `settle_day()` pays each person's labour, pays rations out of the same purse, drifts loyalty, rolls a real escape keyed to the person's id and the day, and lets a yard of desperate people rebel together; the scene applies it when the calendar turns, including days skipped by rest or travel. **L** opens a frozen ledger where **TAB** changes the terms for the whole yard, **ENTER** hands a person to the watch for a bounty and some relief from your name, and **U** unbinds them. Taking and keeping people raises a saved `notoriety`: Unmarked becomes Watched, then Wanted, and at Wanted guards will not speak to you and the merchant will not trade until a handover or release buys the name down. The subsystem obeys the content toggle: with captivity off nobody can be subdued, an existing yard is kept intact and simply stops settling, and the roster, terms, counter and notoriety are optional save keys under schema 2.
- NPC progression: the market climbs while you are away. Every resident's cultivation is a pure day-by-day simulation from the world seed and their stable id (`NpcProgress`): archetype discipline adds insight, higher realms slow the climb, two disciples of the same rank diverge by their own rolls, and at the peak of a realm a breakthrough is a real chance that can fail — resetting the peak's insight, injuring the body for a fortnight and occasionally costing a sublevel. A realm gained is not a label: the person's sheet is regenerated at the new realm, so their attributes, arts and worn gear rise with them, a companion's build follows immediately, and the dossier reads `Cultivation: Foundation Establishment 3 · 62% to the next step`. The town announces at most three breakthroughs or failed attempts per day, and nothing about progression is saved: the seed and the day already decide it, so schema stays 2. Ceilings are data in `data/npcs.json` — a sect master can reach realm 8, an outer disciple 4, a farmer 2 — and a failed attempt's injury window is real lost cultivation time.
- Emergent stories: the market keeps its own record. `data/stories.json` gives each kind of day its weight, venue, goal and headline template, and `Stories` (`game/systems/stories.gd`) draws two beats per day from the residents whose ambitions and current routine fit — a price argument in the market, a lesson drilled until dark, a harvest, beast tracks at the gate. Real progression events are entries too: a breakthrough is announced, and a failed one becomes a request, because the injured cultivator needs a Mending Pill. Each entry names its actors and a deterministic handful of **witnesses** standing in the same place, and talking to a witness repeats the newest rumour they know (four days before it ages out). An entry with work attached becomes an offer with a deadline: deliver the pill in person and it leaves your satchel when you speak to them, or thin the beasts the watch asked about, two kills per request, paid in spirit stones and regard through the same memory the next conversation reads. **J** opens a frozen chronicle screen listing recent news and open requests. The chronicle is bounded to 40 entries and saved with progress for hunt work, so the record survives a load; everything in it is generated from the seed and the day rather than scripted, and schema stays 2.
- Loot tables: every source of loot is one data-driven table in `data/loot_tables.json` — wild kills, elites, bosses, ordinary containers, sealed chests, ruin caches and the inheritance altar — each owning its roll count, empty chance, rarity weights, slot weights, item-level bonus, minimum rarity and stone purse. `ItemGen` still decides what an item is; `Loot` only decides which roll is asked for, on its own stream, so the same kill always drops the same pieces and editing one weight cannot reshuffle another source. About one wild humanoid in eight turns up as an **elite**: a gold-ringed, tougher, harder-hitting body with its own `elite_died` death channel, its own table and a purse, so a rank can never roll twice. Sealed chests, containers and ruins now draw from their own tables instead of a hard-coded rarity, the boss pays two assured spirit-or-better pieces, and the inheritance altar adds one assured piece of its own on top of the relic and the technique. `DB.validate()` rejects a table with a bad weight, a malformed roll or stone range, a missing source, or a slot that no item base can fill.
- Secondary stats: evasion (rolled by the victim, capped at 55%), armour penetration against real enemy armour, cooldown reduction, crit damage replacing the old constant, out-of-combat health regen that stops when attacking, and realm-based lifespan — all reachable through new loot affixes and shown on the HUD.
- Attribute robustness: raw attributes floor at zero, every percent modifier is floored so cursed gear cripples instead of inverting (movement, attack speed, damage, Qi, cultivation), negative armour is ignored, crit/resist/lifesteal/recovery cap, and attribute costs cannot overflow.
- Character creation: a second screen for origin (Sect Orphan, Merchant's Child, Hunter's Child, Fallen Clan Heir) with a purse, starting method and at most one passive, plus a code-drawn appearance (robe, hair, skin palettes and a presentation line) saved with the character.
- Off-screen simulation: NPCs sleep beyond 1500 units (and inside hidden realms) with no per-frame cost, then wake snapped to the schedule that passed, reporting what changed while the player was away; chunk resources that regrew while unloaded are counted and reported too.
- Navigation and fast travel: a route list of settlement landmarks and discovered sites (T), travel that costs in-game time instead of stones, a waypoint with a HUD compass and distance, waypoint arrival detection, and saved routes and waypoints.
- World locations: deterministic overworld sites per chunk — collapsed ruins (one-shot loot, permanent), spirit ore veins (ore, refills after 10 days) and spirit stone deposits (stones, refill after 7 days) — each carrying its own regrow window in the chunk delta.
- Discovery rewards: the first visit to any site pays spirit stones once and is remembered in the save, so a site cannot be farmed for its discovery.
- Settlement services and economy: a merchant with deterministic daily stock and remembered purchases, buy/sell pricing on one value curve (sell pays 40%), a code-drawn shop overlay (1–6, TAB, E), and an inn that sells eight hours of rest for spirit stones.
- Biomes: four defined biomes in `data/biomes.json` (palette, prop weights, herb resources, enemy tables), assigned per chunk by smooth value noise seeded from the world, with the settlement's surroundings pinned to the starting biome; chunk props, herb species and the creatures that spawn nearby all come from the biome under them.
- Continent geography: a seeded 5×4 lattice of named land regions with terrain, distance tiers from the capital, enforced connectivity, and a code-drawn map (M) that shows where the playable province sits; nothing about it is stored.
- Weather and seasons: four 30-day seasons, six weather kinds drawn from a per-season table, deterministic weather per six-hour block of a given seed, weather-driven ambient light and storm flashes, and a cultivation rate that rain thins and storms charge.
- Interaction: doors that open a building's interior, one-shot containers with deterministic loot, technique manuals, and repeatable examination of scenery.
- Procedural animation: nine clips (idle, walk, run, sprint, attack, dodge, hurt, meditate, dead) with bob, lean, squash and limb swing on the player, NPCs and enemies.
- Attack animation is driven by the same startup/active/recovery frame data as the hit window, so the strike pose cannot drift off the damaging frame.
- Acceleration-based movement (2 400 u/s² accelerating, 3 000 braking), so turns plant instead of snapping.
- Hold-to-sprint at 1.45×, and right-stick aiming that falls back to the mouse.
- One input layer for keyboard, mouse and gamepad; rebinding a key never drops its gamepad button.
- Camera with world bounds (province and realm), five zoom levels, and smoothed follow.
- Y-sorted world: trees, rocks, bushes, buildings, NPCs and the player draw in depth order.
- Roof occlusion: a building fades while the player walks behind it, then returns to full opacity.
- Day/night lighting: `CanvasModulate` ambient tint plus shrine, rift and altar point lights.
- Resolution scaling: 1280×720 canvas, integer stretch on exact multiples, EXPAND otherwise.
- One settlement, 19 scheduled NPCs with generated records, one sect questline with event-driven steps and rewards.
- Hidden-realm framework: layouts are content in `data/hidden_realm_templates.json` (grid, corners, loops, treasures, hazard chance, enemy tier/roster and optional warden), with three authored layouts and boot validation. The rift opens the default 5×4 Tomb of the Hollow Moon; every template is deterministic and flood-fill tested.
- Hidden-realm discovery and access: `data/realm_access.json` places the rift, sets its reveal radius and a deterministic four-days-in-twelve opening, and carries its rumor. Approaching it, hearing a rumor in conversation, or reading the market board discovers it; the portal, map mark and route list then show open or sealed status. Discovery rides the existing saved `Game.discovered` dictionary, legacy saves with realm progress auto-discover, and a sealed rift refuses entry with its next opening day.
- Dynamic world events: `data/world_events.json` authors eight tidings on a deterministic five-day cycle, each with a duration, effects on cultivation, prices, spawns, sect service or rift access, an optional task and a one-time reward. A town herald reads the live tiding, the HUD shows its progress, and a rift convergence is the one gate that overrides the calendar.
- Quest architecture: `data/quests.json` authors a four-quest graph — the opening Azure Cloud invitation, Elder Bai's tempering errand, the market board's ledger contract and Instructor Rui's first descent. A quest declares a giver, prerequisites (`quests`, `any_quests`, `min_realm`, `min_contribution`), ordered steps and an authored reward; a step is single-objective or a multi-objective `all`/`any` branch, so the tempering errand is satisfied by five beasts or four herbs. Talking to a giver accepts every quest whose gates are met, the scene reports real events (kills, gathered herbs, the shrine, purchases, crafts, realm entry, altar trials and returns) through one `report()` call, and only a completed quest pays, once. `QuestLog.validate` rejects duplicate ids, empty or malformed steps, unknown prerequisite ids, self-links and cycles, unknown objective kinds and rewards that pay nothing or name unknown grants. The HUD tracker shows the two most recent open quests. Saves keep a versioned per-quest state table beside the old primary mirrors, so a pre-M67 save resumes its initiation step and counters unchanged.
- Sect storylines: `data/sect_storylines.json` gives each of the twelve houses a three-chapter arc built on one shared ladder of stakes — the welcome, the fault line, the reckoning — but never one shared kind of work. Cliffspire asks for duels and forge-work, Green Hollow for herbs and brews, the Floating Archive for a copied page, and so on. A chapter advances only on the real events the quest log already hears (kills, gathered herbs, the shrine, purchases, forge and cauldron work, realm entry, altar trials and conversations). When its test is paid, the chapter opens a choice between two authored stances; each stance moves that house's regard and pays its own stones, contribution, standing, notoriety, karma or technique/passive. Regard decides which of three endings the arc reaches, and a defiant path can spend it to zero, so the low ending is reachable rather than decorative. The Azure Cloud's arc starts with Elder Bai; the other eleven houses write to the market board, and only one such correspondence may be open at a time. Blood Moon and Frozen Heaven refuse each other outright. **F6** opens a frozen screen listing every arc, its live chapter, that house's regard and the two stances when a decision is pending. Storylines live in `SectStorylines` (`game/systems/sect_storylines.gd`); `SectStorylines.validate` rejects wrong arc counts, two arcs for one house, missing or reused stakes, unknown test kinds, fewer than two stances, stances that change nothing or name unknown grants, asymmetric refusals, prerequisite cycles and endings that cannot resolve. The saved ledger is an optional `sect_storylines` block under schema 2, sanitised on load: unknown arcs and stances are dropped, regard and counters are clamped, and a decided chapter cannot be replayed for a second payment.
- Main narrative: `data/main_narrative.json` carries four archaeological threads of four records each — the Severed Heaven, the Root Question, the Physique Bloodlines and the Pavilion's Book. A record is never handed out: it opens only from real state — a realm discovered, an altar claimed, kills, contribution, work at the forge or cauldron, a rank or the master's seat, a completed quest or house story, a house's regard for you. Opening the archive, or any reported event, reads the world against the ledger; a record opened in one pass can open the next, so progress is never a frame late. Every thread's last record requires records from two other threads, so the four converge without prescribing an order. **F7** opens a frozen archive: four threads, their live progress, the recovered prose with its source, and the exact conditions still missing on the next page. `MainNarrative.validate` rejects wrong thread or record counts, duplicate or malformed ids and colours, empty gates, unknown condition keys, impossible realm/rank/quest/story/site/regard gates, out-of-order chains, first records that start from another record, cycles, and final records that do not converge two other threads. Saves carry only discovered ids: unknown and out-of-order records are dropped, so a hand-edited save cannot skip the archaeology or forge a convergence.
- Endgame: `data/endgame.json` holds one blank page and four resolutions — Mend the Road, Close the
  Door, Keep the Ledger and Leave It Blank. The page opens only when all four narrative threads have
  reached their final records, and each resolution asks a different proof of the run: four claimed
  altars, a founded hall, twenty regard with the Azure Cloud, or, for the refusal, nothing but the
  reading. **F8** shows the four pages, what each promises and costs, and the proof still missing;
  ENTER arms a page and a second ENTER writes it, permanently. The epilogue is kept in the save and
  read again from the same screen, and the death screen carries the page's title. `Endgame.validate`
  checks that the threshold names the final record of each thread, that there are four uniquely named
  and coloured pages with real prose, and that every proof kind is understood and used once. Saves add
  an optional `endgame` block: an unknown page, or one written into a save whose archive does not hold
  all four final records, is dropped.
- Settings and accessibility: `Options` (`game/core/options.gd`) persists high contrast, reduced motion,
  damage numbers, combat sound and volume, and captivity content to `user://options.cfg` — never into a
  run's save, so the choices survive every new life. **F10** opens a two-page screen: DISPLAY applies
  each switch the moment it changes, and CONTROLS rebinds twenty-two keyboard actions by capturing
  one real key, naming any action displaced by a conflict and unbinding with BACKSPACE. Mouse and
  gamepad buttons are never lost to a key rebind. High contrast repaints the HUD with brighter ink,
  an opaque panel and a gold accent; reduced motion removes the impact freeze while damage still
  lands; the volume reaches every combat voice and zero is true silence. Every edge of the file is
  sanitised, so a hand-edited volume, toggle or negative keycode falls back instead of breaking.
- Character sheet: **C** opens six frozen cards read live from the body — identity and age, realm,
  method, root and physique, attributes and derived stats, arts and passives, gear and professions,
  and the house's rank, hall, party and deeds. The sheet owns no state, so it cannot disagree with
  the run it describes.
- Title screen: the game boots to painted key art and three actions — a new life, a continued life
  (the highest populated slot) or quit. Keyboard and mouse both work, the version is printed, and
  the screen hands the main scene a single pending slot rather than owning run state. The title
  uses the same high-contrast palette as the HUD.
- Ambient score: a twelve-second loop synthesized in code, a slow drone under a pentatonic bell
  figure, started on the title and carried across the scene change. It shares the interface volume,
  has its own **Ambient music** switch on the DISPLAY page, and F2 mutes it with the combat voices.
  No audio file ships; the loop is deterministic and loop-seam safe.
- Performance: the HUD now redraws at 30 Hz instead of once per frame and only rebuilds its toast
  list when a toast expires; the standing biome's Qi density is resolved on a chunk crossing rather
  than every frame. Both paths are covered by integration checks that count the work performed.
- Release: version 1.0.1 is carried by the project and the save header, Linux and Web presets ship
  in `game/export_presets.cfg`, and a tag-triggered CI job builds both artifacts.
- One procedural hidden realm with hazards, chests and a one-time inheritance.
- Save/load with atomic writes, sha256 verification, 3 backups, corruption fallback, schema migration.
- Structured logging with an in-memory ring buffer (`Log.dump()`).

## Not implemented yet

code-drawn, with the title key art as the one painted asset); travel between provinces; flight,
domain projection, space folding and the other declared realm capabilities; profession tools,
masters and the deeper economy; NPC deaths and feuds; the player being taken captive rather than
being the captor; additional hidden-realm templates. The 1.0.1 interface, audio and release
packaging are complete; this list is deliberate scope, not missing UI.
